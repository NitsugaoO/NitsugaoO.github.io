## 内容侧专题

### 歌词卡：无声的「按原曲速度」播放器

用户要的是「按原曲速度滚动」。难点不是解析 LRC（一个正则的事），而是**时间
从哪来** —— 没接音频（也不该接：网易云不给 MP3 直链，Meting 代理随时挂），
所以时间由 `performance.now()` 自己走：点开就用时钟计时，每 200ms 拿当前秒数
去 LRC 时间轴里查该高亮哪一行，歌词按真实时间戳滚动、进度条按 `duration` 推进。
相当于一个无声播放器，歌词时间轴与真实听歌一致。

**LRC 获取**（本地跑，存进仓库后前端零外依赖）：

```bash
curl -s "https://music.163.com/api/song/lyric?os=pc&id=<歌曲id>&lv=-1&kv=-1&tv=-1" \
  -H "User-Agent: Mozilla/5.0" -H "Referer: https://music.163.com/" \
  | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{
      const j=JSON.parse(s);
      require('fs').writeFileSync('source/lrc/<歌曲id>.lrc', j.lrc.lyric, 'utf8')
    })"
```

三个坑（都已在代码里处理，改的时候别踩回去）：

1. **LRC 头部混着伪歌词**：`[00:00.00] 作词 : 李健` / `[00:01.00] 作曲 : 李健`
   这类元信息必须过滤，否则显示出来很怪（靠 `LRC_META` 正则）。
2. **纯时间戳的间奏行**：`[02:30.71]` 后面没内容，代表这段没歌词，跳过。
3. **前奏很长**：《贝加尔湖畔》第一句在 `[00:48.20]`。播出按钮后要干等 48 秒，
   所以用 `LYRIC_LEAD_IN = 3` 把起点拨到第一句前 3 秒（已确认用户要这个行为）。

> 网易云还有逐字歌词字段 `klyric`，但这首歌是空的 —— 所以只能做到逐行高亮，
> 做不了卡拉OK式的逐字染色。要逐字得先确认目标歌有 klyric。

⚠️ **侧栏槽位的坑**：`top`（`card_top_self`）在**所有页面**都渲染；
`bottom`（`card_bottom_self`）**只在首页/归档等非文章页**渲染 —— 文章页的
`widget/index.pug` 走的是另一个分支，压根不含 bottom。想在文章页也看到卡片，
就用 `top`。

⚠️ **槽位位置不够用就用 JS 搬**：模板把 `card_top_self` 放在
`.sticky_layout` **外面**，滚动时会跟着跑掉；而目录（`#card-toc`）在里面，
会吸附、一直可见。想让卡片像目录那样「随时挂在右侧」，就得搬进去：

```js
var toc = document.querySelector('#aside-content #card-toc');
if (toc) toc.parentNode.insertBefore(card, toc.nextSibling);
// 没有目录的页面（首页/归档）就 sticky.insertBefore(card, sticky.firstChild)
```

见 `custom.js` 的 `placeLyricsCard()`。**改主题模板很危险（会被 git pull 覆盖），
但用 JS 搬 DOM 很安全。**


### 文章简介怎么才会上首页

主题的 `postDesc` helper（`themes/butterfly/scripts/common/postDesc.js`）按
`index_post_content.method` 决定摘要来源：

| method | 行为 |
|---|---|
| 1 | 只用 `description` |
| **2** | **`description` 优先，没有就截断正文**（当前值） |
| 3 | 总是截断正文（默认值，首页会直接贴正文开头） |

所以在 front-matter 加 `description:` 就够了，首页卡片和 `<meta og:description>`
都会自动用它，**不需要写任何代码**。简介控制在 80 字以内（它在首页是一行小字）。

### 导航结构（已定的决策，别再重推）

菜单只有四项：**首页 / 分类 / 标签 / 关于**。

- **归档不单独占菜单** —— 首页本身就是时间倒序的文章流，归档页只是同一批
  数据的另一种排版，属于重复入口。`/archives/` 页面仍存在，只是不进菜单。
- **分类 = 文件夹**（唯一归属、可层级）；**标签 = 跨文件夹索引**（多对多）。
  两者语义边界就这里，分类页已做成文件夹卡片（`everforest.css` 第十一节）。
- **搜索不合并** —— 它是导航栏的全局入口（任意页面可用），塞进某个页面
  反而是降级。搜索与归档是**两个不同的筛选轴**（关键词 vs 时间）。

### 文章类型：文章 vs 笔记

front-matter 的 `type` 字段区分内容性质（不写 = 普通文章）：

```yaml
type: note    # 笔记/存档，不是给人看的成品
```

- 它与**分类**（主题/文件夹）、**标签**（关键词）是三个正交维度，不要用
  `categories: [笔记]` 或 `tags: [笔记]` 表达类型——那是把两个维度撞在一起。
- 主题会把 `page.type` 拼成 `#body-wrap` 的 class（`type-note`），**不影响**
  布局判断（`globalPageType` 才是真类型），可以拿来做 CSS 区分。
- 数据流：`scripts/library-data.js` 输出 `type` → 首页按 type 分两区
  （文章 / 笔记）→ 文章库列表给笔记加标记。

### 歌曲：lyrics.yml + lrc（管理页可编辑）

- 歌单数据已从 `source/js/lyrics-data.js`（`window.WOOYUN_LYRICS`）**迁到
  `source/_data/lyrics.yml`**，由 `scripts/site-data.js` 输出到 `/site.json` 的
  `lyrics` 字段；`custom.js` 的 `startLyricsCard(songs)` 拿数据，旧的
  `window.WOOYUN_LYRICS` 只作兼容兜底。
- 歌词在 `source/lrc/<id>.lrc`，管理页「歌曲」视图可以增删改歌单、
  直接编辑并保存 LRC（`/api/lrc/:file`，只允许 `.lrc`）。
- 歌单字段：`title/artist/url/lrc/tlrc/duration/lines/added/note/shuffle`。
  `shuffle: false` 的歌不出现在侧栏「换一首」的随机池里。
- 网站歌曲页是 `source/songs/index.md` + `source/js/songs.js`（inject.bottom，
  自检 `#songs-root`），读 `/site.json` 的 `lyrics`，按 `added` 倒序渲染。
  YAML 里的 `added: 2026-10-23` 会被解析成 Date，`scripts/site-data.js`
  和 `admin/content.js` 都做了 `YYYY-MM-DD` 规范化。
- 搜索添加：`GET /api/netease/search?q=`（关键词/分享链接/纯 id）+
  `GET /api/netease/lyric?id=`，后端代理网易云公开接口（需要 UA + Referer），
  前端拿到歌词后走 `/api/lrc/:file` 落盘。网易云接口随时可能失效，
  失败时提示手动粘贴；不要在前端直连（CORS + Referer）。
- **双语歌词**：`tlrc` 指向 `source/lrc/<id>.tlyric.lrc`。`/api/netease/lyric`
  返回 `{lyric, tlyric}`，搜索添加时一起落盘；老歌用卡片上的「拉取翻译」补。
  `custom.js` 的 `build(song, timeline, translations)` 按 `Math.round(time*10)`
  对齐翻译；有翻译时给 `lyrics-track` 加 `has-sub`，所有行统一 3.4em，
  否则播放器 `rowHeight` 实测会错位。歌曲页同理（`lrcToPairs` + 缩进翻译行）。
- 管理页歌曲卡片的日期 + 随机开关用 `.song-extra`（flex），注意
  `.card input { width:100% }` 会把日期撑满，要单独 `width:170px`。
- 改 `scripts/site-data.js` 后要重启 hexo server；`custom.js` 改完普通刷新即可。

### 评论：Giscus（文章 / 关于 / 说说）

- 仓库 `NitsugaoO/NitsugaoO.github.io`，分类用 **Announcements**
  （`DIC_kwDOVL5uls4DJaLq`）：Announcements 类型只有维护者能发 discussion，
  访客只能评论，不会在 Discussions 里乱建楼。
- `repo_id` 用 `gh api repos/<owner>/<repo> --jq .node_id`。
- **分类无法用 API 创建**（GraphQL 没有 `createDiscussionCategory`），
  只能在网页 Settings → Discussions 里建；开启 Discussions 时会自带
  Announcements/General/Ideas/Polls/Q&A 等默认分类。
- 必须手动安装 [giscus App](https://github.com/apps/giscus) 并授权仓库，
  否则 iframe 提示 “giscus is not installed”。
- 映射：文章/关于用 `pathname`；说说用 `specific + term=key`，所以
  `_data/shuoshuo.yml` 每条必须带唯一的 `key`（管理页新建时自动生成）。
- 主题切换：Butterfly 的 `giscus.pug` 会监听 `themeChange`，
  `light_theme` / `dark_theme` 对应 giscus 内置主题或自定义 CSS URL。

### 创建时间 / 修改时间：date 与 updated

- 创建时间 = front-matter 的 `date`，修改时间 = **Git 最后一次提交时间**。
- `_config.yml` 必须写 `updated_option: 'empty'`，否则 Hexo 会用 mtime 覆盖。
- `scripts/updated-from-git.js` 在 `before_generate`（给数据文件用）和
  `before_post_render`（给文章页用）里设置 `post.updated`，优先级：
  **手写 updated > `git log -1 --format=%cI -- <file>` > date**。
- **浅克隆检测**：`git rev-parse --is-shallow-repository` 为 true 时直接
  回退 date。否则浅克隆会把「最新那条提交」当每篇文件的修改时间，全站错成同一天。

三个必改的配套：

1. `.github/workflows/pages.yml` 的 checkout 加 `fetch-depth: 0`。
2. Cloudflare Workers 的构建命令前加 `git fetch --unshallow || true &&`
   （否则 CF 构建里是浅克隆，更新时间会缺失/不准）。
3. **改完 `updated_option` 必须 `hexo clean`**。Hexo 把渲染结果缓存
   在 `db.json`，不清的话文章页的 updated 仍是旧 mtime，看起来像“改动没生效”。

数据流：`library.json` / `feed.json` 带 `updated` → 首页卡片、文章库显示
「创建 · 更新」（两者相同时不重复显示）→ 管理页顶部的「创建 … · 更新 …」
是 `content.js` 读 git 算的（带 HEAD + mtime 缓存，3 秒轮询不会反复跑 git）。

时间格式有两个函数，别串：`formatDate` 用 UTC 分量（还原 js-yaml 解析的
front-matter 日期），`formatLocal` 用本地分量（新建文章 / git ISO 时间）。


## 首页与列表

### 首页：左侧筛选 + 中栏时间流

首页不是主题的原生列表，而是 `source/js/home.js` 接管 `#recent-posts`
重写的：

- 数据：`/feed.json`（`scripts/library-data.js` 生成，文章 + 笔记 + 说说
  合并、按 `ts` 倒序）
- 左列：作者卡（点击进 /about/）+ 筛选按钮（全部/文章/笔记/说说）
- 中栏：混合时间流，按 `kind` 渲染不同卡片

| 数据文件 | 用在哪里 |
|---|---|
| `/library.json` | 文章库页面（**不含说说**，文章库是结构化浏览） |
| `/feed.json` | 首页时间流（含说说） |

说说的 `content` 在 generator 里用 `hexo.render.renderSync({text, engine:'markdown'})`
渲染成 HTML 直接下发，所以支持 Markdown / 图片 / Hexo 标签。
说说日期要手动格式化：YAML 解析后是 Date，`String()` 出来是 ISO 格式。

**置顶**：`feed.json` / `library.json` 都带 `top` 字段（front-matter 的
`top: true` 或 `sticky > 0`）。首页三处用到它：左栏的「置顶」卡片列表、
中栏卡片头部的 `feed-kind--pin` 徽章、以及 `feed.json` 的排序（置顶优先）。
文章库列表用 `lib-pin` 徽章（在日期左侧，和「笔记」同行），
**但文章库不按置顶排序** —— 它是结构化浏览，仍按日期。


## 新增 / 导入文章

新建：

```bash
pnpm exec hexo new "标题"
```

front-matter：

```yaml
---
title: 标题
date: 2026-10-16 14:30:00
tags: [Pwn, 栈溢出]
categories: [CTF]
katex: true          # 需要数学公式时加上
---
```

**导入已有的 md 时**：

1. 保留原 front-matter 中有用的字段（如 `course` / `source`），补上 `categories` / `tags` / `katex`
2. **删掉正文里的一级标题** —— 博客标题由 front-matter 渲染，留着会重复
3. 图片改写成绝对路径 `/images/<目录>/xxx.png`，并把图片复制到 `source/images/<目录>/`
4. 中文标题没问题，Hexo 会做 URL 编码

> ⚠️ **数学公式**依赖 `hexo-renderer-markdown-it` + `@renbaoshuo/markdown-it-katex`
> （配置在 `_config.yml` 的 `markdown` 段）。
> **不要**装已被废弃的 `hexo-renderer-katex`，也**不要**换回 `hexo-renderer-marked` ——
> 后者不解析 LaTeX，还会把 `x_n` 的下划线当斜体标记，直接破坏公式。

## 本地管理页（admin/）

嫌手改 md/yml 麻烦时用：

```bash
cd /c/Users/Agustin/blog && pnpm admin   # → http://127.0.0.1:5173
```

| 文件 | 职责 |
|---|---|
| `admin/content.js` | 数据层：md/yml ↔ JS 对象，所有路径白名单 |
| `admin/server.js` | 127.0.0.1 上的 HTTP 服务：静态页 + `/api/*` |
| `admin/public/` | 无框架的单页 UI（index.html / app.js / style.css） |

能力：文章/笔记、说说、友链、关于、公告的增删改；「站点预览」检查/启动
`hexo server`（4000）并打开对应页面；「重新生成」跑 hexo；
「发布」= `git add -A + commit + push`。Ctrl+S 保存当前页。

地址栏参数：`?view=shuoshuo`、`?file=文章.md`、`?preview=1`（直接进全屏预览）。
编辑器还支持 `?fullscreen=1`（正文+预览全屏）。

**布局坑**：`main` 必须是 `overflow: auto`、`.posts-wrap` 用 `height: auto;
min-height: 100%`，内容超高才能整页滚动；`.editor-head` 里标题/时间放左列
（两行）、`.editor-tools` 单独一列且 `flex-wrap: nowrap`，否则长标题会把按钮挤到第二行。

缩略图点击 → `openLightbox(src)` 大图；站内路径（`/images/`、`/img/`）
弹窗里提供「用系统查看器打开」，后端 `POST /api/open-image` 把路径映射回
`source/images|img` 后用 `cmd /c start "" <file>` 打开（外部 URL 不显示这个按钮）。

图片字段（封面、友链头像）用 `makeImagePreview(getSrc)` 做实时缩略图：
管理页自己已经代理了 `/images/*`、`/img/*`，所以本地路径能直接显示；
外部 URL 也行，加载失败加 `.is-broken` 半透明。

分类 / 标签输入框下面会把**所有文章里出现过的值**汇总成 chips（去重排序），
点一下追加到逗号分隔的输入框；候选每次从 `/api/state` 的 posts 现算，
没有单独的索引要维护。笔记专用的 `course` / `source` 也有表单字段，
留空保存时会被删掉（不会给普通文章塞空字段）。

### 两个容易踩的坑

1. **预览里的图片 404**：Markdown 写的是 `/images/...`，管理页在 5173，
   必须在 `server.js` 里把 `/images/*`、`/img/*` 映射到 `source/images`、
   `source/img`（已做，带路径穿越检查），否则预览一片空白。
2. **预览窗格只有 320px 高**：`.body-wrap` 要 `flex: 1 1 auto; min-height: 0`，
   内层 textarea/预览也 `min-height: 0`；否则它只会拿到内容高度。
3. **`.gitignore` 的 `public/` 会连 `admin/public/` 一起忽略**（目录规则不限于根）。
   已改成 `/public/`。曾经因此把管理页 UI 漏提交两次——只交了 content.js/server.js，
   clone 下来 `pnpm admin` 打开是 404。

「站点预览」的实现：`GET /api/site-status` 用 http 请求 4000 判断是否在跑；
`POST /api/site-start` 用 `spawn('pnpm', ['exec','hexo','server'], { detached:true,
stdio:'ignore', windowsHide:true }).unref()` 拉起，再轮询到 4000 可访问为止。
前端拼当前文章的 URL 打开（permalink `:year/:month/:day/:title/`，`:title`
就是去掉 `.md` 的文件名）。

### 草稿与外部编辑（用户主要在 VSCode 里写）

- 文章状态由**目录**决定：`_posts/` = 已发布，`_drafts/` = 草稿。
  每条记录带 `status`，前端用 `file + currentDraft` 定位（两个目录可能同名）。
- 列表可按 全部/已发布/草稿 筛选；草稿有「转为已发布」（`fs.renameSync` 到 _posts，
  等同于 `hexo publish`，但不用起 Hexo）。
- 「VSCode」按钮 → 后端 `spawn('code', ['-g', file], {shell:true, detached:true})`。
- **自动刷新**：前端每 3 秒 + window `focus` 时拉 `/api/state`，和上次 JSON 比较，
  变了才 render；`state.dirty` 时直接跳过（不把用户正在写的内容冲掉）。
- 「站点预览」用 `hexo server --draft`，草稿也能本地打开；CI 构建不带动参数。

### 说说：VSCode 定位编辑 + 预览

- `content.js` 的 `readShuoshuo()` 会顺带扫描 `^- date:` 的行号，附到每条
  `item.line`，所以「VSCode」按钮能 `code -g shuoshuo.yml:行号` 精准定位。
- `/api/open-vscode` 支持 `{ type:'data', key:'shuoshuo', line }`，
  data 文件走白名单（shuoshuo/site/link），不能传任意路径。
- 「预览」直接调 `/api/preview`（markdown-it + KaTeX），按 textarea 当前值渲染。
- 新建说说必须生成 `key`（评论区用 specific + term=key），管理页已自动生成。

### 两个容易踩的时间 / 样式坑

1. **新建文章的日期不能用 `formatDate`**。`formatDate` 用 UTC 分量是为了还原
   js-yaml 把 `2026-10-14 20:41:00` 解析成 UTC Date 的字面量；而 `new Date()`
   是本地时间，得用 `formatLocal`（本地分量），否则新建文章会差 8 小时。
2. **`.status` 类名被顶栏占了**：`#status` 的 `opacity: 0` 会把列表里同名
   class 的徽章一起隐藏。列表用 `.post-status`，编辑器用 `.status-badge`。

### 数据写回的约定（改 content.js 时别破坏）

- front-matter 字段顺序固定（`FM_ORDER`），数组用 `flowLevel: 1` 保持 `[a, b]` 行内
- YAML 数据文件用 `flowLevel: -1`（全 block，说说的 `content: |` 才能保持可读）
- 日期写成 `YYYY-MM-DD HH:mm:ss`；js-yaml 会把它解析成 **UTC 的 Date**，
  所以还原字面量必须用 `getUTC*()` 分量，用本地分量会整体偏移 8 小时
- 删除文章调 `trash` CLI 进回收站，不直接 `rm`
