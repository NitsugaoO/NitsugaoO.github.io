## 网页字体（JetBrains Maple Mono）

全站统一 **JetBrains Maple Mono**（JetBrains Mono 英文 + Maple Mono 中文的合成字体，中英 2:1 等宽对齐）。
本机 ttf 一个就 18 MB，所以网页用的是**子集化分片**：

| 项 | 位置 / 取值 |
|---|---|
| 分片生成 | `tools/build-fonts.py`（依赖 `pip install fonttools brotli`） |
| 分片文件 | `source/fonts/JetBrainsMapleMono/{400,700}-{latin,han-site,han-common,han-ext}.woff2` |
| `@font-face` | `source/css/fonts.css`（**自动生成，不要手改**） |
| 正文字体栈 | `_config.butterfly.yml` 的 `font.font_family` / `code_font_family` / `blog_title_font` |
| 等宽变量 | `source/css/everforest.css` 第六节的 `--ef-mono` |

四个分片按 `unicode-range` 分工，浏览器只下载页面真正用到的：

| 分片 | 内容 | 体积 |
|---|---|---|
| `latin` | ASCII + 标点 / 符号 + 站内西文 | 26 KB |
| `han-site` | 站点所有文章 / 配置 / 歌词里出现过的汉字 | 336 KB |
| `han-common` | GB2312 一级里本站还没用到的 | 624 KB |
| `han-ext` | GB2312 二级（生僻字） | 831 KB |

**常见页面只需 latin + han-site ≈ 362 KB**（han-common / han-ext 命中 0 就不会请求）。
新增文章里出现字体没有的字 → 管理页 `/?view=fonts` 会黄字列出缺字，点「重新生成子集」；
命令行等价于 `python tools/build-fonts.py`（约 40 秒，重扫全站字符后重建 8 个文件）。

**两个坑**：

1. 生成脚本会**跳过** fenced 代码块、`{% raw %}` 块、行内代码 —— 那里是“演示给人看的写法”，
   改了会把文档示例弄错。
2. `font-display: swap`，首次访问会先显示微软雅黑再切换；字体没下载成功时回退到
   `--ef-mono` 里的 Fira Code / Consolas / 微软雅黑。


## 视觉与素材专题

### 网站图标（favicon）

`_config.butterfly.yml` 的 `favicon` 指向 `source/img/favicon-cloud.ico`（站内文件，
不再用主题自带的蝴蝶图标）。源图是 `source/img/cloud.jpg`（640×640 云海），生成方式：

```python
from PIL import Image, ImageEnhance
im = Image.open('source/img/cloud.jpg').convert('RGB')
im = im.crop((0, 150, 640, 640))                 # 去掉上部纯天空，16px 才看得出云
w, h = im.size
im = im.crop(((w - h) // 2, 0, (w + h) // 2, h)) # 居中正方形
im = ImageEnhance.Contrast(im).enhance(1.12)
im = ImageEnhance.Sharpness(im).enhance(1.5)
im.save('source/img/favicon-cloud.ico', format='ICO', sizes=[(16, 16), (32, 32), (48, 48)])
```

⚠️ 16px 下云海只剩蓝白云斑，**不裁上部天空就是一条浅蓝渐变**，认不出是云。
换源图后重跑上面这段即可；改完要硬刷新标签页（浏览器缓存 favicon 很顽固）。

### 页脚动图的压缩

用户给的原始素材往往是全屏 GIF（例：1920×1080 / 84 帧 / **7.5 MB～30 MB**），
不能直接上站。用 ffmpeg 缩尺寸 + 降帧 + 转动画 WebP
（例：30.7 MB → 400×225 / 10fps / **658 KB**，降了 98%）：

```bash
ffmpeg -y -i 原图.gif \
  -vf "scale=400:-2:flags=lanczos,fps=10" \
  -c:v libwebp -q:v 40 -loop 0 -an mascot.webp
```

要点：

- `scale=N:-2` 的 `-2` 是取偶数宽高（WebP 编码要求）。
- **素材可能是透明背景的立绘**。先查一下：
  `python -c "from PIL import Image; im=Image.open('x.gif'); print(im.mode, im.info.get('transparency'))"`
  有 transparency 就是透明图，转完必须用
  `ffprobe -show_entries stream=pix_fmt` 确认输出是 `argb`（含 alpha）——
  透明立绘可以直接站在页脚上，比不透明背景图好看得多。
- 透明图的 WebP 体积明显大（同一张图：不透明 658 KB → 透明 813 KB），
  所以透明素材优先降宽度而不是降质量，边缘铝齿比模糊难看得多。
- 要裁剪就用 `crop=宽:高:x:y`（偏移靠 `read` 看图反复调），但**先问用户**——
  裁与不裁是审美取舍，不要自作主张。

另外务必提醒用户：**原图留在仓库的 git 历史里会永久占用仓库体积**，
所以只把压好的成品放进 `source/img/`。

### 验证布局：用无头浏览器量像素 ★

改完间距/对齐这类“看着不对”的问题，**不要靠猜**。Windows 上有 Edge，
直接无头截图，再用 Python 逐像素找边缘，能拿到确切数值：

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
  --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=6000 \
  --window-size=1600,1100 \
  --screenshot="C:/Users/Agustin/blog/_shot.png" "http://localhost:4000/"
```

- `--virtual-time-budget=6000` 必须加：页面靠 `fetch` 异步渲染，不加会截到白屏。
- 然后用 PIL 扫描某一行的颜色突变点，就能量出卡片边缘与间距。

**一个真实的闭坑案例**：间距怎么调都不生效，最后发现是选择器写成了
`html.home-mode`，而 JS 把类加在 `<body>` 上 —— **`html.x` 永远不会匹配
`body.x`**。写完带前缀的选择器，先想一下那个类到底挂在哪个元素上。

**第二个闭坑案例（`html .container`）**：分类页/友链页的样式整节失效，
原因是前缀用了 `html .container`。`.container` 只出现在**文章页**的
`article#article-container`；分类、标签、友链、说说这些页面的 DOM 是
`main#content-inner > #page > …`，没有 `.container`。

| 页面 | 正确前缀 |
|---|---|
| 文章页正文 | `html .container`（或 `#article-container`） |
| 分类 / 标签 / 友链 / 说说 / 关于 | `html #page` |

排查套路：`curl -s localhost:4000/分类页 | grep -o 'class="[^"]*container[^"]*"'`
一条都没有 → 那一节的 `.container` 前缀全废了。

## 页面与组件专题

### 首页首次闪烁 / 首屏慢怎么治

首页内容被 `home.js` 换成三栏，但 HTML 里先渲染的是主题的卡片流，
不处理就会“先看到旧页面再跳变”。治法：

1. **`inject.head` 里加内联脚本**，在 `<head>` 阶段就给 `<html>` 打
   `home-pending`（比 body 里的脚本早，不会漏掉第一帧）；
2. CSS 把旧内容藏起来，但用 `:not(.home-split)` 限定，渲染完成后自动恢复：
   ```css
   html.home-pending #recent-posts:not(.home-split) > * { visibility: hidden; }
   ```
3. **4 秒 setTimeout 兜底**：万 `home.js` 没执行（挂了/被拦/网络太慢），
   也不能让首页一直空白。注意兜底是**条件式**的（`!document.querySelector('#recent-posts.home-split')`
   才撤掉标记），渲染成功时不再多此一举。
4. **骨架占位**：脚本 + 数据回来之前，左列和中栏原本是纯空白，屏幕上只剩右栏
   （看起来像“只有右栏”）。`custom.css` 用 `::before` / `::after` 在
   `#recent-posts:not(.home-split)` 上画两块 268px + 中栏的呼吸块，
   窄屏只画一块（真实布局是单列）；`.home-split` 一出现就自动失效。

### 首屏为什么“过一会才出左列”

左列和中栏**都是 `home.js` 用 JS 建的**，右栏（`#aside-content`）是 Hexo
静态渲染的，所以第一帧只能看到右栏。当时的两个瓶颈都修了：

1. **灯箱脚本曾走 jsdelivr**：主题把 `lightbox` 的 `<script>` 放在 `main.js`
   之后**同步**加载，107 KB 的国外 CDN 请求会把后面所有脚本（含 `home.js`）
   一起堵住。现在 `CDN.option.fancybox` / `fancybox_css` 指向仓库内文件
   （`source/js/vendor/fancybox.umd.min.js`、`source/css/fancybox.css`），
   换版本时两个文件都要跟着换（版本号 6.1.14，见 `themes/butterfly/plugins.yml`）。
2. **`/feed.json` + `/site.json` 的请求曾被推到 `home.js` 执行之后**：
   现在 `<head>` 的内联脚本就发起 `window.__homeData`（`Promise.all`），
   `home.js` 直接复用它，不重复请求；两个 JSON 与 HTML 解析并行下载。
3. 站点自己的四个脚本（`custom.js` / `library.js` / `home.js` / `songs.js`）
   在 `inject.bottom` 里全部加了 `defer`：不阻塞解析，彼此仍按顺序执行。

> 量过：本地无限速时三栏出现时间 462ms → 221ms。注意模拟“慢网”要用
> HTTP/2 才准，`python -m http.server` 是 HTTP/1.1（每域名 6 连接），
> 会把本地化后的并发收益吃掉，别拿它的数当结论。

### 正文字号：16px，但不要动 `font.global_font_size`

`_config.butterfly.yml` 的 `font.global_font_size` 是**空值 = 14px**，它同时是
`--global-font-size`，也是全站几十处 `.72em` / `.86em` 的基准。
直接改这个变量会把侧栏、三栏首页、管理页预览一起挤坏。

正确做法：只放大正文容器（`custom.css` 第十三节）：

```css
html #article-container { font-size: 16px; }   /* 14px → 16px */
html #article-container figure.highlight,
html #article-container .code-wrapper { font-size: 14px; }   /* 代码块钉回原大小 */
```

实测（无头 Edge 量 computed style）：正文/段落/列表/引用 14→16px、行高 28→32px、
`h2` 21→24px、KaTeX 16.9→19.4px；`body` 仍 14px、行内 `code` 仍 14px、
首页卡片描述（12.32px）不受影响。代码块曾从 12.88px 被动涨到 14.72px
（`.line` 是 `0.92em`），所以才要那两条钉回去的规则——**改正文后一定要
重量一次代码块**。390px 窄屏无横向溢出。

### 自定义代码块语言（```flag → FLAG）

Hexo 的高亮器在渲染时就把不认识的语言改写成 `plaintext`
（`hexo-util/dist/highlight.js` 里那句 `lang = 'plaintext'`），
**原始名字当场就丢了**，前端再怎么改也拿不回来。

正确解法：在 `scripts/custom-codeblock.js` 里给 highlight.js **注册一个空语言**：
`hljs.getLanguage('flag')` 为真 → 保留原名 →
`<figure class="highlight flag">` → Butterfly 只读
`figure.className.split(' ')[1]`，标签自然就是 FLAG。

想加别的自定义语言，改 `CUSTOM_LANGS` 数组即可（别放 js/python 这类真语言）。

三个坑（都已踩过）：

1. **pnm 下拿不到 hljs 实例**：站点根没有 `highlight.js`，要从 `hexo-util` 的位置
   `require.resolve`——只有解析到**同一个真实路径**，注册才会被 hexo-util 看到。
2. **`before_post_render` 拿到的已是渲染后的 HTML**（含 `<hexoPostRenderCodeBlock>`），
   想在那阶段改写 md 源码的代码块是行不通的（试过，白费功夫）。
3. **改完要 `hexo clean` + 重启 server**：Hexo 会缓存渲染结果，
   `scripts/` 又只在启动时加载。


### ⚠️ 开文章页横幅（top_img）时会踩的坑

`disable_top_img: false` 后，**所有页面**都会去找 `top_img`，而
`index_img` / `default_top_img` / `archive_img` 这些配置项如果写成
**空值**（不是 `false`），主题会把空字符串当成“有图”，于是
首页直接冒出一条 100vh 的主题色横幅。

正确做法：

```yaml
default_top_img: false
index_img: false
archive_img: false
tag_img: false
category_img: false
```

并且给所有**不想显示横幅的页面**（说说/文章库/友链/关于/404）在
front-matter 里写 `top_img: false`；只想给某几篇文章配横幅时，
其余文章也写 `top_img: false`，否则会多出一条空白横幅。

横幅背景是图片，主题默认没遮罩，标题会看不清 —— `everforest.css`
第十四节里加了一层 `rgba(39,46,51,.55)` 遮罩并把文字改成米白。

### 图片点击放大（fancybox）

`_config.butterfly.yml` 的 `lightbox:` 默认是**空值 = 不启用**，必须先写 `lightbox: fancybox`。

但光开配置还不够：主题在页面加载时只扫一次 `img:not(.no-lightbox)`，
把它们包成 `<a data-fancybox="gallery">`。**首页 feed / 说说卡片里的图是
fetch 之后动态插入的，赶不上那一趟**，不会有点击放大。

解法：在渲染完的代码里手动补调一次主题的函数：

```js
if (window.btf && typeof window.btf.loadLightbox === 'function') {
  window.btf.loadLightbox(container.querySelectorAll('img:not(.no-lightbox)'))
}
```

（`btf` 是主题挂到 window 上的工具对象，见 `utils.js`。）

### 九宫格与 fancybox 的冲突

开了 fancybox 后，图片会被包成 `<a><img></a>`，于是
`p:has(> img ~ img)` 这种**子元素**选择器就失效了（直接子是 a 不再是 img），
九宫格会退化成一张张竖排大图。

写法：两种都覆盖 —— `p:has(> img ~ img), p:has(> a ~ a)`，
内部的 `img` 选择器也要同时匹配 `a`。

### 数学公式：说说页 / 首页时间流里的 KaTeX ★

主题把 `.katex` 默认设成 `display: none`（`third-party.styl`），等 JS 加载完
公式样式后再给元素补 `.katex-show`。这个流程**只对静态渲染进 HTML 的文章页
有效**：

- 说说页的内容从 `<script id="shuoshuo-data">` 里 JSON 异步插进 DOM；
- 首页时间流是 fetch `/feed.json` 后插进 DOM；

两者都赶不上那次「加载完再加类」，而且这两处没有 `page.katex` 开关，
主题根本不会加载公式样式 → 公式整块空白（不是没渲染，HTML 里 KaTeX 节点都在）。

当前解法：

1. `inject.head` 引入**本地** `/css/katex.min.css`
   （`source/css/katex.min.css` + `source/css/katex-fonts/*.woff2`，
   从 `node_modules/katex/dist` 复制；只放 woff2 就够，CSS 里的 woff/ttf
   永远不会被请求）。
2. `custom.css` 第九节直接 `html .katex { display: inline !important }`，
   块级公式用 `html .katex-display .katex { display: block !important }`。

**别引 CDN**：jsdelivr 一抖，公式就空白（同一时间 Font Awesome 也会
变成满屏方框，导航图标全是「☒」）。本地文件还能离线看。

### 分隔线：从虚线+图标改成普通横线

主题的 `.custom-hr` 是「2px 虚线 + 一个会滑动的图标」，用于：
文章正文的 `---`、友链页、评论上方（`comments/index.pug` 的 `hr.custom-hr`）、
搜索弹窗里的 hr。

- `_config.butterfly.yml` 的 `hr_icon.enable` 关掉（否则 `:before` 图标还在）
- `everforest.css` 第十六节把 `hr` / `.custom-hr` 覆盖成 `1px solid var(--ef-bg3)`

### 标签为什么是七种颜色

`everforest.css` 4.10 用 `:nth-child(7n+1..7)` 把红橙黄绿青蓝紫轮转给标签。
**侧栏标签云**在 `card_tags.orderby` 用稳定排序（当前 `length`）时颜色才稳定；
用主题默认的 `random` 会让每次构建顺序重洗，同一个标签颜色乱跳。

**标签页（`/tags/`）的底色是主题随机生成的**，不能只改文字色：
`cloudTags` helper（`themes/butterfly/scripts/helpers/page.js`）用
`getRandomColor()` 给每个标签写内联 `style="background-color: rgb(...)"`，
每次渲染都换一批。如果只按 7n 轮转文字色，会撞出「绿底绿字」这种看不见的标签。

正确做法：用 `!important` 覆盖**背景色**（内联样式不是 `!important`，能盖住），
文字统一 `#2d353b`（fg_on_green），hover 用 `filter: brightness(1.12)`。

## 颜色改不动时的诊断法 ★

**这是最耗时的排查**。Butterfly 的颜色有三种存放方式，改错了层就完全不生效。

| 类型 | 怎么认 | 怎么改 |
|---|---|---|
| **CSS 变量** | `--global-bg` 这类，源码里用 `var()` 引用 | 直接改 `everforest.css`（首选） |
| **编译期硬编码** | CSS 里写死 `#49b1f5`，源码是 `$theme-color` 派生 | 改 `_config.butterfly.yml` 的 `theme_color`，或写**更高特异性**的 CSS |
| **内联样式** | HTML 元素上有 `style="color:#999"` | **只能 `!important`**，CSS 变量对它无效 |

### 诊断命令

改完不生效时，先 `hexo generate`，再查旧色值是否还活着、挂在什么选择器上：

```bash
bash "scripts/sync.sh" --check '#78818a'    # 换成要查的色值
```

它会列出该色值在生成的 `index.css` 里残留的所有规则。若某个选择器出现，就说明：
要么它更具体（要复刻选择器），要么它来自内联样式（要 `!important`）。

### 覆盖时的两个陷阱

1. **特异性**：Butterfly 大量使用复合选择器。`figure.highlight pre .python .title` 比
   `figure.highlight pre .title` 高一级，覆盖时要**复刻它的完整选择器**，否则"后加载"也救不了。
2. **明暗两套**：`--ef-*` 已在 `html[data-theme='dark']` 和
   `html:root:not([data-theme='dark'])` 里分别定义，所以**语法色之类的规则只写一套、
   不带主题前缀**即可自动切换。写两套会重复 130 行还容易打架。

### 编译期硬编码（改 CSS 变量无效）

| 位置 | 现象 |
|---|---|
| `$theme-color` 派生 | 导航 hover 下划线、页脚背景、分页器、`a` 链接色等约 50 处 |
| 语法高亮色 | `figure.highlight pre .xxx` 无变量，且**不随明暗切换** |
| 代码块背景 | `[data-theme='dark'] .container pre > code { background: #171717 }`，优先级高于 `--hl-bg` |
| 行内代码 | `$code-background` 是 stylus 变量，不是 CSS 变量 |

## 用角色的语义，别自己造色

`tokens.yaml` 里的名字对应**用途**而非色相：

| 角色 | 用途 |
|---|---|
| `bg0` / `bg1` / `bg2` / `bg3` | 页面 / 卡片 / 浮层 / 边框，逐级变亮 |
| `bg_dim` | 最暗层（页脚、预加载） |
| `fg` `#d3c6aa` | 正文米白 |
| `grey0` / `grey1` / `grey2` | 由暗到亮的三档次要文字 |
| `green` `#a7c080` | 主强调色 |
| `red` / `orange` / `yellow` / `aqua` / `blue` / `purple` | 语法色与状态色 |
| **`fg_on_green` `#2d353b`** | **强调色底上的文字** |

> 绿底上的文字一律用 `fg_on_green`，别硬编码黑或白。
> 页脚、目录选中项、按钮 hover 用的都是它。
